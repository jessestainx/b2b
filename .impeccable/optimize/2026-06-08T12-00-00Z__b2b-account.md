# Optimize — Conta B2B (`b2b/account`)

## Bottleneck identificado

Todas as páginas `customer_account` carregavam `b2b-account-pages.css` (**154 KB**), bundle com:
- `pages.css` (51 KB) — necessário
- `dashboard.css` (39 KB) — só no dashboard
- `login.css` (23 KB) — só no auth
- `register.css` (51 KB) — só no cadastro

**Desperdício típico em reorder/crédito/aprovações:** ~103 KB de CSS parse bloqueante + duplicata em `b2b_quote_index.xml`.

## Mudanças aplicadas

| Mudança | Impacto |
|---------|---------|
| `customer_account.xml` → `pages.css` only | −103 KB CSS bloqueante nas páginas operacionais |
| `b2b_quote_index.xml` mantém `pages.css` (rota 1col sem `customer_account`) | Sem duplicata nas rotas com handle global |
| `b2b-pages-css.phtml` → `media="print"` + `onload` | `awa-b2b-pages-late.css` (56 KB) não bloqueia FCP |
| `b2b-dashboard-css.phtml` → mesmo padrão async | 4 folhas dashboard fora do critical path |
| §69 `content-visibility` em aprovações/ERP/listas | Menos paint em listagens abaixo da dobra |
| `contain: layout style` na sidebar desktop | Isola reflow da coluna principal |

## CSS por rota (pós-optimize)

| Rota | Bloqueante | Async |
|------|------------|-------|
| Reorder / crédito / aprovações | `account-b2b.css` + `pages.css` | `awa-b2b-pages-late.css` |
| Dashboard | + `dashboard.css`, distill, reset | refinement, visual-upgrade, late, audit |
